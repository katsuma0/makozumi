How It Works

The cryptography behind a Makozumi tag

The idea: a signature only one person can write

Each Makozumi tag stores a short message (the product's name, maker, date, and serial number) together with a digital signature of that message. The signature is created with a private key that only the maker holds. This website contains only the matching public key, which can check signatures but cannot create them.

That asymmetry is the whole trick: anyone in the world can verify a tag, but nobody can mint a new one — copying the code from one product onto another product of the same kind is the only "attack" left, and the serial number in the signed payload exposes duplicates.

The scheme: ECDSA over the curve P-256

Makozumi uses the Elliptic Curve Digital Signature Algorithm on the NIST curve P-256. The curve is the set of points (x, y) satisfying

y² ≡ x³ − 3x + b  (mod p)

where p is a fixed 256-bit prime. Points on this curve form a finite abelian group: there is a rule for "adding" two points that yields a third point on the curve. Repeated addition gives scalar multiplication, kG = G + G + … + G (k times), for a fixed public base point G of large prime order n.

Keys

  • Private key: a random integer d with 1 < d < n.
  • Public key: the curve point Q = dG.

Computing Q from d is fast (double-and-add, like fast exponentiation). Recovering d from Q is the elliptic curve discrete logarithm problem (ECDLP) — for a 256-bit curve the best known attacks need about 2¹²⁸ group operations, which is computationally infeasible. This is the elliptic-curve analogue of the discrete logarithm problem in (ℤ/pℤ)*, and it is why publishing Q on this very page gives forgers nothing.

Signing a tag (done once, offline, by the maker)

  1. Encode the product info as a message m and hash it: e = SHA-256(m). The hash compresses the message to a fixed-size value and makes it infeasible to find a second message with the same hash.
  2. Pick a fresh random nonce k, compute the point kG and take r = (kG)ₓ mod n (the x-coordinate).
  3. Compute s = k⁻¹(e + r·d) mod n — this is where the private key d enters. (k⁻¹ is a modular inverse, found with the extended Euclidean algorithm.)
  4. The signature is the pair (r, s) — just 64 bytes.

Verifying a tag (done by this page, every time you tap)

  1. Recompute the hash e = SHA-256(m) from the payload in the URL.
  2. Compute u₁ = e·s⁻¹ mod n and u₂ = r·s⁻¹ mod n.
  3. Compute the point P = u₁G + u₂Q using only public values.
  4. Accept iff Pₓ mod n = r.

Substituting Q = dG shows P = (u₁ + u₂d)G = kG exactly when the signature was made with the true private key — so a genuine tag always verifies, and forging one without d would require solving the ECDLP.

What's actually on the NFC chip

The tag stores a single URL:

https://katsuma0.github.io/makozumi/#<base64(payload)>.<base64(r‖s)>

Tapping the tag opens this site; the JavaScript here runs the verification above using the browser's built-in WebCrypto implementation of ECDSA. If even one bit of the payload is altered, the hash e changes and the check fails — the page shows NOT AUTHENTIC.

Why "somewhat basic" crypto is enough here

Nothing on the tag is secret — the security rests entirely on one clean, standard hardness assumption (ECDLP) and one standard primitive (ECDSA + SHA-256), both of which secure TLS, passports, and payment cards today. The system needs no server, no database, and no secrets on the tag or in this site.
